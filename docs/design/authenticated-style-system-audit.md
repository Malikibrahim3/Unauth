# Authenticated style-system audit

Date: 2026-07-14 · Branch: `ui-craft-overhaul` · Scope: `app/(app)/**`, authenticated-consumed `components/**`. Out of scope: public landing, `components/claims/**` / `app/(app)/claims/**` (in-flight uncommitted work on this branch — see note at the end).

This audit is the input to the `styles/authenticated/` consolidation. It does not redesign anything; it records what exists today, what's duplicated, and where it's going. It supersedes nothing in `docs/design/authenticated-component-system.md` or `docs/design/old-theme-eradication-report.md` — both remain accurate about *intent* (one authoritative signed-in scope, landing tokens excluded); this audit adds what those two documents didn't catch: a second live token layer that duplicates the first, and a stale third doc.

## 4. Portal / dead-code verification (blocked §1's globals.css deletion row — deletion cancelled as a result)

Checked whether any authenticated overlay (Modal, Drawer, Toast, tooltip, command palette, dropdown) renders via `ReactDOM.createPortal` outside the `.ua-app`/`.ua-auth-surface` DOM subtree. No `createPortal`/Radix/Headless-UI usage exists anywhere in the repo — `Modal.tsx`, `Drawer.tsx`, `Tooltip.tsx` all render as ordinary in-tree `<div>`s, and `CommandPalette.tsx`'s native `<dialog>` stays a true DOM descendant of wherever it's mounted (inside `.ua-app` via `AppHeader`). But the check surfaced a *structurally equivalent* escape that isn't a portal: `ToastProvider` renders its toast container as a plain sibling `<div>` outside `.ua-app` (see §1's corrected row) because the context providers wrapping the authenticated tree in `app/(app)/layout.tsx` produce no DOM node, so `.ua-app`'s sibling toast div never inherits its scoped tokens. **Result: the globals.css deletion is cancelled for this pass** — the block is not dead, and this audit documents the actual live consumer instead of asserting a false all-clear.

## Note on scope boundary

`components/claims/**` and `app/(app)/claims/**` are excluded from every migration/consolidation action in this pass. Git status shows uncommitted, in-flight changes there (`ClaimsQueueClient.tsx`, `claimReviewState.ts`) belonging to the parallel "craft overhaul" effort (`docs/IDE_PROMPT_authenticated_ui_craft_completion.md`). Touching those files here would risk clobbering that work and conflating two unrelated efforts. Their duplication is fully documented in the migration register with an explicit owner, not silently dropped.
