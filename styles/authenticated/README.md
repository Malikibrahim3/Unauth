# Decision Ledger — Instrument Grade workspace rules

**Status:** binding contributor loader for authenticated product styles.

**Implementation authority:**
[`../../docs/IMPL_decision_ledger_instrument_grade_final_iteration.md`](../../docs/IMPL_decision_ledger_instrument_grade_final_iteration.md)

This file is a compact source-facing contract. The implementation document
wins visual, phase, ownership, state, and completion conflicts. Product truth,
security, permissions, provenance, audit, financial, route, query, mutation,
export, and merchant-control contracts remain binding.

## Surface modes

One visual authority supports four deliberate densities:

- Operational for `.ua-app`;
- Editorial for public storytelling and legal reading;
- Entry for auth and onboarding; and
- Pocket Brief for browser and helpdesk hosts.

The modes may vary density and composition. They retain one cool-neutral
palette, one violet interaction voice, one semantic state system, one icon
grammar, and one source-to-outcome visual language.

## Direction

Unauth is an evidence-and-decision instrument. Every route should expose:

1. identity and scope;
2. the dominant operating object;
3. source facts and their provenance;
4. any gap or inference;
5. the next merchant-owned action; and
6. the recorded outcome.

The finish comes from financial precision, evidence continuity, typography,
alignment, responsive priority, and state quality. It does not come from iOS
imitation, glass, gradients, glow, card soup, tiny metadata, decorative charts,
or visual cohorts.

## Fixed foundations

- `--ua-*` is the sole authenticated token namespace.
- Product shell geometry is 200px expanded navigation, 56px compact
  navigation, and a 52px utility toolbar.
- The authenticated content frame is at most 1600px.
- Settings use a 204px local index at wide desktop sizes.
- Product radii are 8px controls, 12px isolated surfaces, and 16px overlays.
- Inter carries interface and financial text.
- Inter Tight is reserved for deliberate public display roles.
- DM Mono is reserved for identifiers, hashes, keys, code, and payloads.
- Product text never renders below 12px.
- Money, dates, quantities, and table values use tabular numerals.
- Violet means action, focus, selection, or current primary data.
- Semantic colour carries meaning only and always has a text or glyph cue.
- Inline work is flat. Elevation belongs to genuinely floating layers.
- Dark mode preserves the same hierarchy and meaning.

## Canonical compositions

- `DecisionHeader` owns identity, operating sentence, essential state, scope,
  and a restrained action group.
- `WorkbenchPage` owns registries and queue work.
- `DetailPageShell` owns dossiers and contextual decisions.
- `SettingsPageShell` owns configuration documents.
- `RegistrySurface`, `BoardSurface`, `BuilderShell`, and `FormDocument` own
  their task-specific work geometry.
- `EvidenceThread`, `FinancialEquation`, `SourceBeacon`,
  `DecisionSentence`, `ActionDock`, and `RecordedOutcome` provide the
  recognisable Unauth grammar.

One perimeter owns a work object. Nested bordered cards are prohibited.
Durable navigation uses tabs or an index; temporary filters use filter
controls. Segmented controls are limited to true mutually exclusive view
modes.

## Controls and forms

- Buttons, links, icon actions, fields, switches, checks, radios, and action
  rows share dimensions, focus, pending, disabled, invalid, and coarse-pointer
  behaviour.
- Use at most one filled primary action per local region.
- Consequential actions state their effect before commit.
- Fields keep label, hint, error, read-only, pending, and success in one
  deterministic structure.
- Placeholder text never replaces a label.
- Disabled content never relies on opacity alone.

## Registries and charts

- `RegistrySurface` owns its command bar, count, selection/bulk state,
  rows/table, and pagination.
- `DataTable` and `DataTableServer` remain canonical.
- Row actions are keyboard reachable and portal above overflow owners.
- Horizontal overflow remains inside the declared work surface.
- Every chart answers one merchant question and is useful before interaction.
- Exact values, scope, null/unavailable distinctions, keyboard access, and a
  table or text equivalent are mandatory.
- Decorative sparklines, waffle charts, gradients, and theatrical chart
  motion are prohibited.

## Overlays and feedback

- Modal, Drawer, menu, Tooltip, Toast, and Command Palette use one portal and
  layer system.
- Only the topmost overlay handles Escape.
- Modal backgrounds are inert.
- Focus is restored to the trigger.
- Tooltips and menus avoid viewport and overflow clipping.
- Toasts are secondary confirmation, never the sole durable outcome.
- Successful consequential actions become `RecordedOutcome` in place.

## States and accessibility

Loading, slow loading, first-run empty, legitimate empty, filtered empty,
zero, partial, stale, disconnected, unavailable, denied, locked, validation,
pending, conflict, success, failure, destructive, and not-found states remain
visually and semantically distinct.

- Skeletons mirror final family geometry.
- Known context stays visible during recoverable errors.
- Authenticated work is optimised for 1024px and wider.
- Browser zoom or text scaling may not replace a critical task with a blocking
  boundary; use accessibility reflow.
- WCAG 2.2 AA, keyboard completion, 200% zoom, text spacing, forced colours,
  reduced motion, dark mode, and coarse-pointer targets are release gates.

## Execution and verification

Execute `IG-00` through `IG-16` in the implementation authority. The migration
is a hard cutover:

1. update shared responsibility before route-local composition;
2. migrate every state and viewport with the route;
3. delete the superseded primitive or style after its last consumer moves;
4. update the discovered visual-owner evidence;
5. run the active visual-system verifier and functional parity tests; and
6. inspect the real route at 1440px, 1280px, 1024px, and accessibility reflow.

Functional flags such as `CONNECTION_HEALTH_V2_ENABLED`,
`WORK_COCKPIT_V2_ENABLED`, and `CASE_WORKSPACE_V2_ENABLED` remain product
controls. They never select an appearance.
